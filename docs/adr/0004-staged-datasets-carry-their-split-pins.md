# Staged datasets carry their split pins

Status: accepted
Source: Lauren Olinger's ask of 2026-09-14 (train the fish detector in VEGA and compare it against the runs the fish experiment already produced), specified in `/mnt/rip/vicarius_drive/docs/superpowers/specs/2026-09-14-vega-fish-box-training-set-design.md`; the comparability rule it serves is `docs/adr/0003-runs-compare-only-on-the-same-split-and-metric-family.md`.
Last updated: 2026-09-15 (LO)

A dataset staged from outside TCRMP often arrives with models already trained on it, and the split those models were scored on is a fact about the dataset, not about the run that reads it. The fish photo dataset staged on 2026-09-15 is the case in point: 7572 images, 14130 boxes, 34 classes, six finished detection runs from an October 2025 ablation, and a train, valid and test folder tree recording the split those runs were trained and scored on. VEGA's detection splitter drew its own seeded split, so a retrain here would have held out different images from every one of those six runs, and ADR 0003 would then have marked each pair "not comparable" and refused to rank them: the module could have trained a fish detector, and could not have said whether it beat the one already on disk. We decided that a staged dataset may carry its own split pins, written by the stager (`scripts/_boxes/ingest_yolo_boxes.py`) as `split_pins.json`, one train, valid or test assignment per staged image basename, and that the detection splitter (`scripts/TCRMPtrain_oceankindCV/src/detect_dataset.py`) replays those pins before any seeded draw. The split manifest then records `holdout_mode: "staged"` and names the file the pins came from in `pins_source`. The proof is on disk: the imported lab at `inprocess/_models/fish_photo_28feb25_paper/dataset/split_manifest.json` and the VEGA training project at `inprocess/run_26-09-15_LO_train_fish_photo_28feb25/step6_trainModel/dataset/split_manifest.json` both replayed 7572 pins into train 5300, valid 1514 and test 758, and both carry split fingerprint `f4f9263d8334e606`, so the runs card can rank an imported run against a VEGA retrain.

## Considered options

- Split the staged dataset here, as VEGA always had, and accept that an imported model and a VEGA retrain are not comparable. Rejected: the point of importing the six runs was to have a baseline, and the runs card would have shown every one of them de-emphasised beside a number it could not be ranked against.
- Import the source experiment's published scores as ledger rows, so the table has numbers without re-scoring anything. Rejected: those numbers were measured by another installation, and the ledger is the record of what VEGA measured. The re-scoring showed why it matters: run3_heavy_augment reads box mAP50 0.9008 here against the 0.9042 recorded where it was trained, because this module runs ultralytics 8.4.38 and that experiment ran 8.3.222, which integrates average precision differently. A row saying 0.9042 would have claimed a measurement VEGA never made.
- Replay the pins, re-score every imported run in VEGA, and let the ledger hold only VEGA's own numbers. Chosen.

## Consequences

- The split fingerprint identifies the split rather than the seed. Two runs built from the same pins agree on the fingerprint whatever validation and test fractions the Train panel was given, because the fractions only decide a draw that never happens; two runs built from the same seed and different pins do not.
- `holdout_mode` in `dataset/split_manifest.json` now takes the value `staged` beside the existing `lab-random`, and a rebuild that replays a manifest's pins keeps whatever mode that manifest already recorded, because replaying a pin never relabels the holdout that made it. Before 2026-09-15 every detection build recorded `lab-random`, which misdescribed a dataset whose every image came from a published experiment; a manifest written earlier still reads that way and is not corrected retroactively.
- A staged dataset with no `split_pins.json` behaves exactly as it did before: the seeded draw makes the split and the manifest records `lab-random`. Coral Intel, staged without pins, is unchanged.
- A pins file that cannot be read stops the build by name rather than falling back to a draw, because a silent fallback would produce a split that looks pinned in the panel and is not. The Bounding Boxes dataset card shows the same state as "unreadable" so the operator fixes the file before training.
- An imported lab is scored, never asserted: `scripts/_boxes/import_external_runs.py` writes no `rounds.csv` row and no champion record, and a score reaches the ledger only from a VEGA Evaluate pass, which records the metric family and the split fingerprint beside it.
