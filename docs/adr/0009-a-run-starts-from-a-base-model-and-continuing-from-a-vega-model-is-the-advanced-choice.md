# A run starts from a base model, and continuing from a VEGA model is the advanced choice

Status: accepted
Source: [2026-09-21-vega-starting-model-and-training-data-design.md](/mnt/rip/vicarius_drive/docs/superpowers/specs/2026-09-21-vega-starting-model-and-training-data-design.md), against Lauren's brief of 2026-09-21: "make it way more clear what data we're using and how we're setting it up. I do not want to see the wall of models trained on all of the training data forever. Tell me what you mean by pretrain versus fine-tune. Should be starting from the basic YOLO models and then an advanced dropdown for fine-tuning and other refining of existing models."
Last updated: 2026-09-21 (LO)

The Train Model panel contradicted itself. Verified from screenshots at 946 and 1280 px on 2026-09-21: the champion line read "the model VEGA starts from everywhere unless another is picked", while the Base model picker beneath it defaulted to `yolo11m-seg.pt`, a base checkpoint, not the champion. One `Base model` select mixed three things: a "Continue from a previous run" group of earlier VEGA runs (champion first), the five YOLO11 base checkpoints, and five YOLO26 checkpoints, and two buttons ("Full retrain preset (recommended)" and "Fine-tune preset (fast loop)") switched the same select between a base checkpoint and the champion's weights, with the difference explained only in their tooltips. "Pretrained" appeared in copy with nothing on screen saying what was pretrained on what, and the trainer never forwarded a `pretrained=` argument at all. No count of images, labels or the train, validation and test split showed before Start Training; the transect holdout rule lived only in a checkbox tooltip, and a box project showed nothing about its split at all.

We decided that a VEGA run starts from a base model, one of the YOLO11 checkpoints Ultralytics trained on COCO (a set of everyday photographs), by default, and that continuing from an earlier VEGA run's weights is a separate, advanced choice a person makes deliberately, never a hidden default. The Starting model select on the Train Model panel now lists base checkpoints only. A "Continue from a VEGA model (advanced)" disclosure, closed by default, holds the earlier-run picker (champion first, then this project's runs, then other projects, then runs trained outside a project), the freeze-layers field, and a note that VEGA lowers the learning rate to 0.001 and freezes the first ten layers when a run is chosen there, restoring both values when the choice is cleared. The two preset buttons and their server routes (`/api/step/6/presets/finetune` and `/retrain`) are removed, because their two outcomes are now the form's default state and the advanced disclosure: the Refine panel's after-export card keeps two plainer-named buttons, "Train a new model" and "Continue from the champion", instead. The "Trained runs" table (23 runs from 3 labs and 7 projects, unbounded by construction), which used to sit between the training source and every training control, moves off the Train panel entirely into a closed "All trained models" disclosure on the Evaluate panel. A new read-only route, `GET /api/step/6/source_summary`, answers the image, label and split counts the Train panel now shows before training starts, so the person can see what they are about to train on.

## Considered options

- Delete the runs table rather than move it. Rejected: it is the only place other projects' and imported runs can be scored and promoted, so removing it would remove a capability, not just tidy the screen.
- Keep the two preset buttons ("Full retrain preset" and "Fine-tune preset") and only fix their tooltips. Rejected: the buttons hide the same contradiction under two labels; the clearer fix is to make the default state of the form the retrain case and a closed disclosure the continue-from case, with no button needed to switch between them.
- Drop YOLO26 from the starting-model list, since it is newer and its export problems are still open. Rejected: the recipe `config/presets/yolo26l_heavy_seg_aug.yaml` names YOLO26 weights, and a recipe may only name weights the picker offers, so YOLO26 stays as a last, labelled optgroup.
- Offer training from random weights as a third starting choice. Rejected: nothing in VEGA has ever started from random weights, and adding the option now would answer a question nobody asked while adding a third case to explain.
- Rename the contract ids the runs card carries (`s6-runs-card`, `_step6_runs.html`) to match its new home on the Evaluate panel. Rejected for this change: three test suites pin those ids, and a rename would cost more than the move is worth right now; it is left as an open follow-up.

## Consequences

- The Train Model panel's default state trains from a base model with no button press required; the "Continue from a VEGA model (advanced)" disclosure is the only way to continue from an earlier run, and choosing a run there disables the Starting model select and says why.
- The vocabulary is fixed: base model, train from a base model, and continue from a VEGA model are the only three ways VEGA describes what a run starts from, defined in [../../CONTEXT.md](../../CONTEXT.md). "Fine-tune" is no longer a VEGA-facing name for the default path; it survives only as what "continue from a VEGA model" is, in that glossary entry's own line.
- The champion is the first choice under Continue from a VEGA model and the model Model Inference uses unless another is picked; it is not what a run starts from unless it is chosen there. A reader of `champion.json` should not assume every run was trained from it.
- The runs table's fragment, stylesheet and script keep their contract ids (`s6-runs-card`, `_step6_runs.html`, `orchestrator_runs.*`) on the Evaluate panel; a rename to match its new home is an open follow-up.
- `GET /api/step/6/source_summary` is a new, read-only server contract: it writes nothing and never builds the dataset, so it carries no data-dictionary descriptor of its own.
