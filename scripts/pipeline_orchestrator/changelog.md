# pipeline_orchestrator changelog

- 2026-10-15 (LO): never-delete review fixes. _superseded.py gains is_superseded_path (the recursive readers _matrix/builder.py ledger and legacy discovery, _matrix/cellinfo.py segmentation_files, check_project_integrity.py stray-tmp walk, _expertids/importer.py, annotation_record_paths and the Step 4.test source check now skip moved-aside folders), a shared image list that includes .webp .bmp .gif .jfif .heic .heif, and a safer tree rule (a tree is removed only when every regular file is a known non-image type; anything else is moved). Destinations are claimed exclusively (os.link, os.symlink or os.mkdir) with the suffix before the extension (X-1.jpeg), so concurrent moves cannot overwrite. reset_step also moves outline records and label folders (segmentations.json, label_provenance.csv, export_manifest.csv, all_labels/) and any file of an unlisted type; plain tables, logs and model weights are still removed. The routing flatten moves one test-points overlay per frame into a single _superseded/<stamp>/routed_test_pts/ folder per pass and reports the count. Retracted review items go to <expert library>/_superseded/<stamp>/review_items/<uid>, outside the public site's git tree, whose .gitignore now lists _superseded/ and is healed line by line on every ensure_repo. New tests: tests/test_superseded_helper.py, _matrix/tests/test_superseded_readers.py, _reefreview/tests/test_review_removal_not_published.py, and additions to pipeline_orchestrator/tests/test_images_never_deleted.py. - rationale: a moved-aside copy must never be counted as live work, and a retracted crop must never be re-published.
- 2026-10-15 (LO): images are never deleted. New scripts/_superseded.py moves an image, or a folder holding one, to <base>/_superseded/<YYYYMMDD-HHMMSS>/<relative path> (never overwriting, never pruned by any code). Used by prune_unreferenced_raw (unused routed images are set aside, which also removes the Low res name collision), _clear_routed_input and _flatten_routed_input (year folders and colliding images), the step4test reset (the whole annotation folder moves to <project>/_superseded/<stamp>/), project_manager.reset_step (numbered resets of steps 1 to 8 set image-holding content aside; CSVs, logs and weights are still removed), and ReviewRepo.remove_item/remove_project. A folder with no image in it (click prompts, caches) is still removed. New test: pipeline_orchestrator/tests/test_images_never_deleted.py. - rationale: Lauren's rule of 2026-10-15; a project's images are the one thing its annotations cannot be rebuilt without.
- 2026-10-15 (LO): annotated-project guard, second pass. Choose Images, the numbered resets of steps 1 to 3, and Open now also protect Step 5 (Segment Images) work: count_annotated_frames reads every segmentations.json under step5_segmentImages as well as the 4.test export and counts a shared frame name once (an unreadable one is unknown and blocks). Runs of steps 1 and 2, /api/step/1/link and /api/remap/apply are refused with the same kind of sentence as the Step 3 run, and the generic reset of steps 1, 2 and 3 is refused with the count. Open refuses to build a routing from scratch on an annotated or unknown project that has no saved click points; on an unannotated project a re-route first removes from routed_input/raw every image no record names, so toggling Low res only can no longer pair an old full-resolution image with rescaled points. The 4.test reset confirm now counts reviewed or exported frames (reviewed outlines included), says so in the sentence, and the response key is annotated_count. - rationale: a re-route that keeps old images under new points, and a reset that skips reviewed work, both lose annotation integrity quietly.
- 2026-10-15 (LO): annotated-project guard and Step 3 recode path. Incident 2026-10-05: Step 3 was re-run on a project with annotated frames, the next Open found the new selection newer than the cached click prompts, and _clear_routed_input removed routed_input/raw, which every all_images link and segmentations image_path_abs points into (556 annotated frames lost their images). New count_annotated_frames reads segmentations.json (reviewed or exported frames; a missing file is zero; an unreadable or oddly shaped file is unknown and blocks, never zero). The Step 3 run route answers 409 with one sentence naming the annotated count when it is above zero or unknown. Open never re-routes such a project (the annotator opens on the existing routing and the stale selection is a WARNING line in the run log and the route warnings); _clear_routed_input never removes routed_input/raw under any caller, so a legitimate re-route on an unannotated project adds new images beside the old. The step4test reset answers 409 while frames are exported unless the request carries confirm_exported equal to the exported count (the word unknown when the record cannot be read); orchestrator.js reopens the existing confirm modal with the count and sends it. select_images.py looked for the species recode in a folder that does not exist, so pre-2020 points were never remapped while the log said remapped; it now takes --remap-log (the project's step 2 remap_log.json, passed by _run_step3), applies it, and logs plainly when no remap applies; a damaged log is an error. New tests: pipeline_orchestrator/tests/test_annotated_project_guard.py, TCRMPcvr_chooseImages/tests/test_species_remap_path.py. - rationale: an annotation is only as durable as the image it points to.
- 2026-09-27 (LO): VEGA annotator tidy-up plan, no-re-screening across projects (Task W2): a new cross-project ledger (_reefreview/screening.py, built on the coverage matrix) answers which labels are already screened for an image in another project. _run_step3 writes prior_screening_input.json before every Step 3 run and passes it to select_images.py's new --prior-screening flag, which drops a frame screened for every one of this project's target labels from both the selection and the reserve pool, and records the counts (skipped_fully_screened, partly_screened) in selection_summary.json; omitting the flag leaves select_images.py byte-identical to before. Every annotator launch, configure (step4test) and resume (step4loop) alike, refreshes prior_screening.json in the project's step4test export dir with the partly-screened frames' screened labels and every other project's accepted masks for them, so the combined annotator can show them as locked previews instead of asking a reviewer to redo work another project already finished. A screening or write failure is logged via vic.note and never blocks Step 3 or a launch. The Step 3 completion panel shows one line naming both counts when the flag was used and found something to report. New tests: _reefreview/tests/test_screening.py, TCRMPcvr_chooseImages/tests/test_prior_screening_exclusion.py, pipeline_orchestrator/tests/test_prior_screening_launch.py.
- 2026-09-27 (LO): annotation safety-net plan, Task T2: every stop of a combined annotator or Edit Masks process (_kill_all_annotators, Stop, /api/project/quit, the step4test/step4loop resets, editmasks stop and reset) now flushes that process (POST /api/flush) before signalling it, so unsaved review edits reach disk first; a failed flush is logged (port and reason) and the stop still proceeds. A tracked port is only flushed once runner.is_running(key) confirms that key still owns a live process, since kill() never clears runner.ports and a dead key's stale port can be reused by an unrelated listener. step4loop/run flushes AND fully stops any live step4test/step4loop annotator BEFORE the seeder rewrites segmentations.json, not merely before the later kill, because the annotator's own flush is a blind dump of its in-memory dict that would otherwise erase the newly seeded masks. restart_reef_point_seg.sh and run_pipeline.sh flush only an annotator-owned listener (its pid's /proc/<pid>/cmdline matched against the same two entry scripts the orchestrator checks) in 5080-5089 and 5096 before their kill sweeps, never an unrelated service sharing the range. A 2xx from /api/flush is not read as a clean save on its own: _flush_annotator and the two restart scripts' _flush_and_report both parse the JSON body against the exact keys _flush_result_fields sends (TCRMPclip_combinedAnnotate/src/app.py): merged/taken_from_disk for a plain merge, conflict/conflict_file/both_sides for one that also hit a frame edited both here and on disk, and the legacy status=="merged" shape, still accepted. Either way the conflict file or the merge counts are logged; an unresolved conflict with no ok field still counts as a failed flush even though the HTTP status was 200. Every pipeline_orchestrator test that can reach _kill_all_annotators or a stop route (test_annotate_routes.py and ten others) now stubs appmod._flush_annotator and guards socket.socket against a real connection to 127.0.0.1:5050 or 5080-5089, closing a gap where the flush-before-kill change made those tests open a real socket. New test: pipeline_orchestrator/tests/test_flush_before_kill.py.
