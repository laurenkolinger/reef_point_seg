# pipeline_orchestrator changelog

- 2026-09-27 (LO): VEGA annotator tidy-up plan, no-re-screening across projects (Task W2): a new cross-project ledger (_reefreview/screening.py, built on the coverage matrix) answers which labels are already screened for an image in another project. _run_step3 writes prior_screening_input.json before every Step 3 run and passes it to select_images.py's new --prior-screening flag, which drops a frame screened for every one of this project's target labels from both the selection and the reserve pool, and records the counts (skipped_fully_screened, partly_screened) in selection_summary.json; omitting the flag leaves select_images.py byte-identical to before. Every annotator launch, configure (step4test) and resume (step4loop) alike, refreshes prior_screening.json in the project's step4test export dir with the partly-screened frames' screened labels and every other project's accepted masks for them, so the combined annotator can show them as locked previews instead of asking a reviewer to redo work another project already finished. A screening or write failure is logged via vic.note and never blocks Step 3 or a launch. The Step 3 completion panel shows one line naming both counts when the flag was used and found something to report. New tests: _reefreview/tests/test_screening.py, TCRMPcvr_chooseImages/tests/test_prior_screening_exclusion.py, pipeline_orchestrator/tests/test_prior_screening_launch.py.
- 2026-09-27 (LO): annotation safety-net plan, Task T2: every stop of a combined annotator or Edit Masks process (_kill_all_annotators, Stop, /api/project/quit, the step4test/step4loop resets, editmasks stop and reset) now flushes that process (POST /api/flush) before signalling it, so unsaved review edits reach disk first; a failed flush is logged (port and reason) and the stop still proceeds. A tracked port is only flushed once runner.is_running(key) confirms that key still owns a live process, since kill() never clears runner.ports and a dead key's stale port can be reused by an unrelated listener. step4loop/run flushes AND fully stops any live step4test/step4loop annotator BEFORE the seeder rewrites segmentations.json, not merely before the later kill, because the annotator's own flush is a blind dump of its in-memory dict that would otherwise erase the newly seeded masks. restart_reef_point_seg.sh and run_pipeline.sh flush only an annotator-owned listener (its pid's /proc/<pid>/cmdline matched against the same two entry scripts the orchestrator checks) in 5080-5089 and 5096 before their kill sweeps, never an unrelated service sharing the range. A 2xx from /api/flush is not read as a clean save on its own: _flush_annotator and the two restart scripts' _flush_and_report both parse the JSON body against the exact keys _flush_result_fields sends (TCRMPclip_combinedAnnotate/src/app.py): merged/taken_from_disk for a plain merge, conflict/conflict_file/both_sides for one that also hit a frame edited both here and on disk, and the legacy status=="merged" shape, still accepted. Either way the conflict file or the merge counts are logged; an unresolved conflict with no ok field still counts as a failed flush even though the HTTP status was 200. Every pipeline_orchestrator test that can reach _kill_all_annotators or a stop route (test_annotate_routes.py and ten others) now stubs appmod._flush_annotator and guards socket.socket against a real connection to 127.0.0.1:5050 or 5080-5089, closing a gap where the flush-before-kill change made those tests open a real socket. New test: pipeline_orchestrator/tests/test_flush_before_kill.py.
